# r2ghidra component guide

This independent repository owns the radare2-to-native-decompiler bridge. Paths and commands below are relative to this root. The [workspace map](../AGENTS.md) describes the host; its C source conventions do not replace this repository's existing C/C++ style. Follow nearby bridge code and the current build definitions.

For commits, follow [the shared prospective attribution rule](../AGENTS.md#shared-prospective-commit-attribution).

## Source and integration owners

- `src/` owns plugin commands and host integration. Start with `src/R2Architecture.cpp` for native architecture/calling-convention selection, `src/R2TypeFactory.cpp` for type registration/resolution, and `src/R2Scope.cpp` for function prototypes, variables and storage. Keep RE semantics at these code owners or the engine's patch/specification owners rather than duplicating them here.
- `src/R2TypeDeclaration.cpp` translates the host's shared declarations and reverse types behind `R2TypeFactory`; declaration syntax and target-Sdb-backed layout remain host-owned at `../libr/util/type_decl.c` and `../libr/util/type_layout.c`, with the public API in `../libr/include/r_util/r_type.h`. `src/R2PrintC.cpp` specializes pointer rendering using the existing native pointer representation and the engine's narrow printer hook.
- `meson.build` owns the plugin and `pcode-xml-test` targets, C11/C++20 settings and the current `r_core` dependency (`>=6.1.4` outside the MSVC-specific library path). `Makefile.acr`, `src/Makefile` and `ghidra/deps.mk` own the Make path; `./configure` generates the root `Makefile`. Check the applicable Make, Meson and static integration followers when changing source lists or dependencies.
- `ghidra/` owns processor-language compilation and installation using the engine's specifications and Sleigh compiler. The plugin and its runtime language files must match; moving a checkout does not configure runtime language selection.
- `r2plugin/` owns static XPS integration with the host. See [r2plugin/README.md](r2plugin/README.md) and [the host XPS procedure](../libr/xps/README.md) before changing that build path.

## Two distinct engine directories

- `ghidra-native/` is the editable independent engine repository, excluded by this repository's root-anchored ignore. Read [its AGENTS.md](ghidra-native/AGENTS.md) before engine changes, and run Git in that root; this parent does not track the child or report its changes.
- `subprojects/ghidra-native/` is the build-managed engine copy, not the editable checkout. `subprojects/ghidra-native.wrap` is the sole engine URL/revision owner: Meson reads it and `subprojects/ghidra-native.mk` derives Make settings from it. Changing the editable engine does not automatically change the build-managed copy or pin.
- [doc/win16-fmovmem.md](doc/win16-fmovmem.md) provides the qualified local-engine population and private-build procedure. Preserve its existing-path refusal and matching plugin/language inputs. The Make subproject manager supports fresh acquisition and revision changes in clean, unprepared Git checkouts, but refuses a prepared or dirty checkout before fetching or switching to a different pin. It does not stash changes or remove `patch.done` to force a transition; preserve user bytes and use a fresh matching tree instead. `make mrproper` deletes the managed engine and zlib directories and is not routine validation cleanup.
- The engine's shared preparation runner validates the ordered patches and prepared source inputs during Make/Meson preparation and Meson build reuse. Stale or ambiguous preparation refuses without changing source bytes; preserve changes and use a fresh matching checkout or prepared distribution, never remove `patch.done` and retry on that tree. Matching prepared distributions remain Git-free. Paired flat native objects, paired processor `.sla` outputs and the documented imported Make test target's narrowly classified object/dependency/executable outputs do not invalidate preparation; canonical inputs, including generated parsers, remain checked. The [engine guide](ghidra-native/AGENTS.md) and [test procedure](ghidra-native/tests/README.md) own the exact output shapes and preparation requirements, not a blanket exemption for imported build directories or targets.

## Build and verification

- Use the intended radare2 executable on `PATH` and its development package through `PKG_CONFIG_PATH`; inspect `pkg-config --modversion r_core` before configuring. Use `meson setup <build-dir>` and `meson compile -C <build-dir>` for the normal Meson build, or the bounded targets and unpublished-local-pin procedure in the product document above. Do not replace the pin to work around fetch availability.
- `test/db/extras/` owns plugin behavior regressions; `test/Makefile` runs them through `make -C test`. Ensure the tested executable actually loads this plugin and the matching language files rather than another installation.
- `test/pcode_xml.cpp` owns the focused native p-code XML encoder test. Build `pcode-xml-test` with Meson, then run `meson test -C <build-dir> pcode-xml --print-errorlogs`; compiling the executable alone does not run it. Engine regression tests belong to the editable engine's local guide.
- For combined local qualification, enable `-Dghidra-native:tests=true` in the fresh bridge Meson build and run the registered `ghidra-native-unittests`, `patch-preparation` and `pcode-xml` tests. Use a task-scoped `TMPDIR` for disposable preparation-test copies and repeat a matching bounded build after DATA/x86 language compilation to check reuse of that same engine source.
- XPS Make/Meson reuse and packaged-distribution Make builds reach the same preparation runner through their own build dependencies. Qualify those consumer boundaries separately; standalone native or combined bridge Meson results do not establish XPS host linkage, the full bridge Make build or runtime readiness. The packaged Make path validates matching preparation without Git acquisition; the normal revision manager requires a Git checkout.
- For documentation-only changes, resolve affected paths and inspect shell syntax without running build/install commands. Run `git diff --check` and inspect this repository's diff/status separately from the host and engine.
